### Hi, I'm Sadad.

I'm an **AI and software engineer based in Kuala Lumpur**, working across applied AI, backend systems, and full-stack products. My projects connect retrieval and models to the parts people actually use: APIs, interfaces, background jobs, and evaluation pipelines.

The question that keeps showing up in my work: **what would convince someone this system works?** In ProofHire, that means tracing generated claims back to code. In Driftline, it means testing against future data and keeping the failed experiments. In SAFE-RAG, it means investigating answers that look supported but cite the wrong regulatory scope.

**Open to early-career Software Engineering, AI Engineering, and ML Engineering opportunities.**

**Fraud detection that accounts for drift.**

Replays historical IEEE-CIS transactions through a streaming pipeline, serves an XGBoost model through ONNX, and uses drift monitoring to trigger retraining with a shadow evaluation gate.

`Redpanda / Kafka API` `PyFlink` `XGBoost` `MLflow` `Kubernetes`

**Look inside:** temporal leakage checks, GraphSAGE experiments, training-serving skew, and documented load-test findings.

## How I approach engineering

- **Make claims traceable.** Keep the source, the experiment, and the assumptions close to the result.
- **Evaluate the failure cases.** Leakage, missing evidence, provider outages, and state transitions are part of the product.
- **Own the path to the user.** I enjoy moving between data, backend logic, and the interface that makes a system useful.
